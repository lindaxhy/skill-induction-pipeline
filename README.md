# Skill Induction Pipeline

A framework for distilling human judgment from examples into reusable LLM skill files — no fine-tuning required.

Given a directory of examples, the pipeline induces a **skill file** (a structured system prompt) that encodes:
- **Features** — rubric dimensions or style fingerprints extracted from examples
- **Prototypes** — annotated calibration examples (full text, never truncated)
- **Tools** — step-by-step scoring or generation instructions

The skill file is used as a system prompt at deployment and outperforms zero-shot baselines on the same task.

---

## Routing: Signal Type × Output Type

The pipeline is chosen by two independent axes.

### Signal type — what your examples contain

| You have... | Signal type |
|-------------|-------------|
| Examples with explicit scores or category labels (essays + grades, resumes + ratings) | **S** |
| A collection of examples you consider representative — no numeric labels | **E** |

### Output type — what the induced skill will do

| You want the skill to... | Output type |
|--------------------------|-------------|
| Score, classify, filter, or rank new items | **discriminative** |
| Generate new content matching the style or quality | **generative** |

Signal S always produces a discriminative skill. Signal E can produce either type.

## Task Directory Structure

Prepare a directory with this layout:

```
my-task/
├── config.md              # Required — signal type, output type, task description
├── examples.csv           # Your examples (or examples/ with one file per example)
├── dev.csv                # Optional — held-out examples for evaluation
└── output/                # Generated by pipeline — skill file lands here
    └── my-task-skill.md
```

### Data Format

**Signal S (`examples.csv`):**

```
input_text,score,domain
"The essay text...",0.82,science
"Another essay...",0.41,history
```

The `score` column holds the gold label; `domain` is optional, used only when sub-groups have meaningfully different score distributions.

**Signal E (`examples.csv` or individual files in `examples/`):**

```
text
"A strong example of the target style..."
"Another example of the target style..."
```

Or: one `.txt` file per example in `examples/`.

### `config.md` Templates

**Signal S (labeled examples → discriminative skill):**

```markdown
# Task Config

**Signal type**: S
**Output type**: discriminative

## Signal S fields
- Input columns: [input_text]
- Label column: score
- Group column: domain   ← omit if no sub-groups

## Task description
Evaluate essay quality on a 0–1 scale. Higher scores indicate stronger argumentation,
evidence use, and clarity of expression.
```

**Signal E (curated examples → generative skill):**

```markdown
# Task Config

**Signal type**: E
**Output type**: generative

## Signal E fields
- Style name: "Yejin Choi abstract style"
- Paper type: empirical   ← position | empirical | benchmark | training (optional)
- Temporal period: 2020-2024   ← optional

## Task description
Generate NLP paper abstracts in the style of Yejin Choi's group.
Given a paper's introduction, produce an abstract matching their style.
```

## Usage

Point Claude Code at your data directory:

```
Use the skill-induction skill on my-task/
```

The pipeline will:

1. Read `config.md` and your examples
2. Run induction on the Signal S or Signal E path
3. Assemble the skill file
4. If `dev.csv` is present: compare against zero-shot baseline and optionally run up to 3 rounds of targeted refinement
5. Write the final skill to `output/<task-name>-skill.md`

No human checkpoint is required during induction — the pipeline runs end-to-end. If you want to inspect the induced skill before using it, just open the output file; it is plain markdown.

## Pipeline Components

```
SKILL.md                   ← Main orchestrator (routing logic, config format, examples)
agents/
  labeled-inducer.md       ← Signal S: Steps S1–S4 (rubric → distribution stats → calibration examples → diagnostic annotations)
  unlabeled-inducer.md     ← Signal E: Steps E1–E4 (example organization → style fingerprint → reference selection → annotations)
  assembler.md             ← Skill file assembly (discriminative + generative templates)
  evaluator.md             ← Optional: Phase 1 baseline comparison + Phase 2 iterative refinement (≤3 rounds)
scripts/
  lib.py                   ← Shared helpers: LLM adapter (OpenAI-compatible), metrics (Pearson / QWK / F1 / ROUGE-1)
  score_candidate.py       ← Score a skill against a zero-shot baseline on a dev set
```

## Common Pitfalls

| Pitfall | Symptom | Fix |
|---------|---------|-----|
| Truncating examples | Skill underperforms baseline | Never truncate — the pipeline handles full text automatically |
| Multi-population data without `Group column` | One group's metric collapses | Set `Group column` in `config.md` so S1 uses per-group stratified extremes instead of global quintiles |
| Vague section 5 mechanisms (Signal E) | Outputs generic; model reverts to direct statements | Re-run induction on a tighter / more consistent subset of examples so the extractor has a clearer common signal |
| Near-duplicate examples | All generated outputs feel the same | Curate for variety across topics, lengths, or moods before invoking the pipeline |
| Length anchor mismatch | Systematic ROUGE drop | Leave length unconfigured unless induction and evaluation examples are closely matched in length |
| Rubric / fingerprint quality poor on one draw | One bad induction output | Re-run the pipeline — the inducer uses a different random sample each call |

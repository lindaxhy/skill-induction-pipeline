# Skill Induction Pipeline

A framework for distilling human judgment from examples into reusable LLM skill files — no fine-tuning required.

## How It Works

Given a directory of examples, the pipeline induces a **skill file** (a structured system prompt) that encodes:
- **Features** — rubric dimensions or style fingerprints extracted from examples
- **Prototypes** — annotated calibration examples (full text, never truncated)
- **Tools** — step-by-step scoring or generation instructions

The skill file is then used as a system prompt to outperform zero-shot baselines on the same task.

### Two Signal Paths

| Signal | You have... | Output skill type |
|--------|-------------|-------------------|
| **S** | Labeled examples (essays + scores, items + ratings) | Discriminative (scorer / classifier) |
| **E** | Curated examples only — no numeric labels | Discriminative or Generative |

## Task Directory Structure

Prepare a directory with this layout:

```
my-task/
├── config.md              # Required — signal type, output type, task description
├── examples/              # Positive examples (individual files, or examples.csv)
│   ├── example1.md
│   └── example2.md
├── negatives/             # Optional (Signal E) — counter-examples / near-misses
│   └── counter1.md
├── test/                  # Optional — held-out input + gold output for evaluation
│   ├── test_input.md
│   └── test_gold.md
└── output/                # Generated by pipeline — skill file lands here
    └── my-task-skill.md
```

### `config.md` Template

**Signal S (labeled examples → discriminative skill):**
```markdown
# Task Config

**Signal type**: S
**Output type**: discriminative

## Signal S fields
- Input columns: [input_text]
- Label column: score
- Group column: domain   ← omit if no sub-groups

## Task description
Evaluate essay quality on a 0–1 scale. Higher scores indicate stronger argumentation,
evidence use, and clarity of expression.
```

**Signal E (curated examples → generative skill):**
```markdown
# Task Config

**Signal type**: E
**Output type**: generative

## Signal E fields
- Style name: "Yejin Choi abstract style"
- Paper type: empirical   ← position | empirical | benchmark | training
- Temporal period: 2020-2024
- Negatives available: true

## Task description
Generate NLP paper abstracts in the style of Yejin Choi's group.
Given a paper's introduction, produce an abstract matching their style.
```

## Usage

Point Claude Code at your data directory:

```
Use the skill-induction skill on my-task/
```

The pipeline will:
1. Read `config.md` and examples
2. Run induction (S or E path)
3. **Pause for your review** at key checkpoints
4. Assemble the skill file
5. Evaluate vs. baseline if `test/` is present
6. Write final skill to `output/<task-name>-skill.md`

### Human Review Checkpoints

**Signal S — after rubric induction:**
The pipeline shows the induced rubric. Edit it if you see spurious correlations (e.g., rubric encodes group identity rather than quality).

**Signal E — after fingerprint extraction (section 5 — unique mechanisms):**
This step requires your attention. LLMs produce abstract category names; you need to convert them into named, quoted, effect-explained constructions. One hand-curated mechanism here is worth five auto-generated ones.

## Pipeline Components

```
SKILL.md                   ← Main orchestrator (routing logic)
instruction.md             ← Full user guide with data format details
agents/
  labeled-inducer.md       ← Signal S: Steps S1–S4 (rubric → distribution → examples → annotations)
  unlabeled-inducer.md     ← Signal E: Steps E1–E4 (fingerprint → review gate → examples → annotations)
  assembler.md             ← Skill file assembly (discriminative + generative templates)
  evaluator.md             ← Baseline comparison + iterative refinement (≤3 rounds)
```

## Common Pitfalls

| Pitfall | Fix |
|---------|-----|
| Truncating examples | Never truncate — full text required for rhythm and closure patterns |
| Multi-population data with global quintiles | Set `Group column` in config.md for per-group stratification |
| Vague section 5 mechanisms (Signal E) | Hand-curate: name it, quote ≥2 source lines, explain effect |
| No counter-examples for sharp-boundary style | Add 2–3 near-miss negatives to `negatives/` |
| Near-duplicate positive examples | Curate for variety — all outputs will feel the same otherwise |
